The `import` statement lets you split a Nano project across multiple files and reuse code written by others without copying it by hand. When the compiler encounters an `import`, it reads the named file and inserts its contents at that exact point in the source, as if you had written the code inline. This means imported identifiers are immediately available to every statement that follows the `import` line, with no separate linking step required at the language level.

## Syntax

```text
import <name>
```

`<name>` is the file or module identifier, without a file extension for local files or as a URL path for remote packages:

```text
import mathutils
import github.com/example/nanolibs/vectors.n
```

## Search Order

When you write `import mathutils`, the compiler looks for the file in the following order:

<Steps>
  <Step title="Same directory">
    The compiler checks the directory that contains the file currently being compiled. This is the most common case for splitting a project into multiple `.n` files.
  </Step>
  <Step title="Defined directory">
    If a package search directory has been configured (e.g. via a compiler flag or environment setting), it is searched next.
  </Step>
  <Step title="System PATH">
    The compiler walks the directories listed in the system `PATH` environment variable, allowing globally installed Nano packages to be imported by name alone.
  </Step>
  <Step title="GitHub URL">
    If the import name begins with a URL (e.g. `github.com/...`), the compiler fetches the file directly from that remote location and compiles it without requiring a manual download.
  </Step>
</Steps>

## GitHub Imports

Nano can import source files directly from GitHub. Provide the full URL path to the `.n` or `.ns` file:

```text
import github.com/example/nanolibs/strings.ns
import github.com/example/nanolibs/mathutils.n
```

Because the file is fetched and inserted at compile time, your project always uses the version of the file at that URL. This means a project shared on GitHub can be compiled by anyone without manually downloading its dependencies — a simple recompile picks up the latest imported file automatically.

## Package Files (`.ns`)

Nano packages use the `.ns` file extension. Inside a `.ns` file, identifiers whose names begin with `__` (two underscores) are **reserved** for use by that package. Attempting to define a `__`-prefixed name outside of a `.ns` file raises `ERR_RESERVED_NAME` (error code 15).

```text
# vectors.ns  (a package file)
var num __x = 0
var num __y = 0
```

```text
# main.n
import github.com/example/nanolibs/vectors.ns

var num magnitude = __x   # __x is now available here
```

## Example: Local Multi-File Project

```text
# utils.n
var num PI = 3

# main.n
import utils          # inserts utils.n here

var num area = PI     # PI is available because utils.n was inserted above
```

<Note>
  `import` inserts the named file's source at the import location during compilation. There is no separate linking step — variables, functions, and list declarations from the imported file are available to all code that appears after the `import` line, just as if you had typed them directly into the file.
</Note>

<Tip>
  For large projects, organise reusable code into `.ns` package files and import them by name or URL. The `__` namespace prefix prevents your package's internal variables from colliding with names defined in the files that import it, keeping the global variable table clean even as your project grows.
</Tip>
